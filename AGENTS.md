# AGENTS.md — правила работы ИИ с этим репозиторием

## Статус проекта

Это **боевой** автоторговый бот на **mainnet** (Polymarket → сигнал, Lighter → исполнение). Ошибки в коде стоят реальных денег и могут задеть соседний бот Donchian на том же VPS.

Относись к репозиторию как к критичному production-сервису: высокая ответственность, нулевая терпимость к халтуре.

## Качество кода (обязательно)

Пиши код **современным, качественным, production-ready** способом.

- **Без костылей.** Нет «временно так», «потом поправим», «для отладки оставим».
- **Без затычек.** Нет silent catch, магических флагов «на всякий случай», дублирующих обходных путей вместо исправления причины.
- **Без мусора.** Не оставляй мёртвый код, закомментированные блоки «на память», лишние файлы, шумные логи, неиспользуемые зависимости.
- **Чётко и понятно.** Имена, границы пакетов, ошибки и состояния должны читаться без археологии.
- **Эффективно.** Минимальные аллокации и сетевые round-trip там, где идёт критичный путь входа/выхода; без преждевременной «архитектуры ради архитектуры».
- **Явные инварианты.** Таймауты, дедлайны, flatten, halt, kill-switch, idempotency ордеров — проектируй так, чтобы ambiguous exchange state не терялся.
- **Тесты на риск.** Меняешь исполнение, fill-confirm, stop, flatten, clock/window — добавляй или обновляй тесты рядом с кодом.
- **Секреты.** Никогда не коммить `.env`, ключи, токены, дампы с реальными credentials. В диагностике — только redacted.

Стиль: следуй существующим паттернам репозитория (Go packages, React dashboard). Не раздувай diff посторонним рефакторингом.

## PROJECT_MAP.md — обязательный рабочий инструмент

В корне лежит [`PROJECT_MAP.md`](PROJECT_MAP.md) — сжатая карта репозитория для ИИ.

### Зачем

Карта нужна, чтобы работа ИИ была **быстрее, точнее и дешевле по контексту**: сначала ориентир по карте, потом точечное чтение файлов — не полный обход дерева «на всякий случай».

### Как работать с картой (постоянно)

1. **В начале задачи** открой `PROJECT_MAP.md` и найди нужный слой/пакет/файлы по карте.
2. **Во время работы** опирайся на карту для навигации: кто за что отвечает, где контракт стратегии, где исполнение, где UI.
3. **После изменений**, которые двигают структуру, ответственность пакетов, ключевые потоки или важные entrypoints — **сразу актуализируй** `PROJECT_MAP.md` в том же изменении (или сразу после).
4. **Не дублируй** в карте длинные спецификации: для стратегии ссылайся на `docs/`, для деплоя — на `INSTRUCTIONS.md`. Карта = индекс + ответственность + «куда смотреть».
5. Если карта и код расходятся — **исправь карту** (или код, если карта отражает целевой контракт и это согласовано). Устаревшая карта хуже отсутствия карты.

Карта не заменяет чтение кода. Она заменяет слепой поиск.

## Сравнение live с бэктестом

Когда пользователь просит прогнать бэктест на накопленных live-окнах или сравнить live с моделью — запускай `scripts/live_vs_backtest.py` на TSV-вставке дашборда. Не пиши новый прогон и не выбирай окна по CLOB `prices-history`: первый history print опаздывает на 10–15+ секунд и набирает лишние сделки.

Контракт скрипта, его не менять «по пути»:

- Гейт — наша `p_up` на :00. Фаворит ≥ 0.65 (`p_up` ≥ 0.65 лонг, ≤ 0.35 шорт).
- Цена — Binance BTCUSDT 1s: вход = close T+1, стоп 0.125% по high/low с T+2 по T+299, иначе close T+299. Стоп в модели всегда −12.5 bps. Секунды из дневных zip в `new-algotrading-adventure/data/binance/btcusdt_1s/daily/`, дыры — REST klines.
- Mean / sum / WR — только фактические входы (вкладка сделок, есть ret bps). Skip, который прошёл гейт, скрипт печатает отдельно и в среднее не кладёт, пока пользователь явно не попросит включить.
- Зазор live−модель сравнивай с запасом из `docs/POLY_LIGHTER_STARTPACK_1_1.md`: красная линия ~1.5 bps, весь mean edge 1.72 bps.

Пример, который должен сходиться с ночью 2026-11-21 21:30Z–03:25Z: `python scripts/live_vs_backtest.py scripts/testdata/dashboard-2026-11-21-night.tsv` → mean бэктеста −1.44, live −1.58, зазор −0.14, skip 23:30 вне среднего.

## Жёсткие ops-инварианты (не нарушать)

- Отдельный Lighter-аккаунт от Donchian.
- Отдельный Telegram bot token.
- Дашборд на **8081** (Donchian занимает 80).
- На рестарте бот может flatten'ить позицию **своего** аккаунта — путаница счетов = чужая позиция закрыта.

## Definition of done для агента

- Изменение решает задачу без регрессии критичного пути (arm → decide → send → fill/stop → exit/flatten).
- Нет временных костылей в merge-ready виде.
- Тесты/проверки по затронутому слою проходят.
- `PROJECT_MAP.md` актуален, если структура или ответственность файлов изменились.
- Секреты и live-данные не утекли в git.
